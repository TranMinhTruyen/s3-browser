S3Browser - profile test thủ công dùng chung cho các phương thức đăng nhập (dựng ở sprint-11)
==============================================================================================

Tài liệu test thủ công, KHÔNG phải requirement. Mọi tài khoản bên dưới chỉ dùng cho
MinIO/LDAP/Floci chạy local bằng Docker, không dùng cho môi trường thật.

  PHẦN A (mục 1-7): provider MinIO - Access key, Anonymous, MinIO STS, LDAP.
  PHẦN C (mục 14-16): provider MinIO bật TLS - OIDC (Keycloak), Certificate (mTLS) và CA certificate file.
  PHẦN B (mục 8-13): provider AWS, giả lập bằng Floci - Access key, AWS CLI profile,
                    Assume role, AWS SSO, Default chain, Anonymous.

  CÁCH NHANH để dựng môi trường trên máy test: dùng Docker Compose trong thư mục này
  (xem README.txt). Mục 5 và mục 11 bên dưới là cách dựng thủ công từng bước.

4. Lưu ý về MinIO khi bật LDAP
------------------------------

  - Khi đã bật LDAP, user nội bộ của MinIO (tạo bằng `mc admin user add`) KHÔNG còn quyền:
    vẫn đăng nhập được nhưng mọi thao tác đều Access Denied. Vì vậy access key cố định phải
    tạo gắn với user LDAP (`mc idp ldap accesskey create`).
  - MinIO STS (AssumeRole) chỉ chạy được bằng tài khoản root. Access key của user LDAP gọi
    AssumeRole sẽ bị AccessDenied. Muốn test quyền hạn chế thì dùng Policy như P7.
  - Tài khoản root vẫn dùng bình thường, các profile cũ dùng root không bị ảnh hưởng.

5.1. Network và MinIO

  docker network create s3_browser_test_app-network
  docker run -d --name minio_s3_browser_test --network s3_browser_test_app-network \
    --restart unless-stopped -p 10010:10000 -p 10011:10001 \
    -e MINIO_ROOT_USER=admin -e MINIO_ROOT_PASSWORD='MinioRoot#2026' \
    minio/minio:RELEASE.2025-04-22T22-12-26Z \
    server --address :10000 --console-address :10001 /data
  docker exec minio_s3_browser_test sh -c \
    'mc alias set local http://127.0.0.1:10000 "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD"'
  docker exec minio_s3_browser_test mc mb --ignore-existing local/demo-photos

5.2. OpenLDAP

  docker run -d --name openldap_s3_browser_test --network s3_browser_test_app-network \
    --restart unless-stopped -p 10389:389 \
    -e LDAP_ORGANISATION="S3Browser Test" -e LDAP_DOMAIN="s3browser.local" \
    -e LDAP_ADMIN_PASSWORD='LdapAdmin#2026' \
    osixia/openldap:1.5.0

  Chờ khoảng 10 giây cho LDAP khởi động xong rồi thêm user và group:

  docker exec -i openldap_s3_browser_test ldapadd -x -H ldap://localhost \
    -D cn=admin,dc=s3browser,dc=local -w 'LdapAdmin#2026' <<'EOF'
  dn: ou=users,dc=s3browser,dc=local
  objectClass: organizationalUnit
  ou: users

  dn: ou=groups,dc=s3browser,dc=local
  objectClass: organizationalUnit
  ou: groups

  dn: uid=ldap-rw,ou=users,dc=s3browser,dc=local
  objectClass: inetOrgPerson
  uid: ldap-rw
  cn: LDAP ReadWrite
  sn: ReadWrite
  userPassword: LdapRw#2026

  dn: uid=ldap-ro,ou=users,dc=s3browser,dc=local
  objectClass: inetOrgPerson
  uid: ldap-ro
  cn: LDAP ReadOnly
  sn: ReadOnly
  userPassword: LdapRo#2026

  dn: cn=s3-writers,ou=groups,dc=s3browser,dc=local
  objectClass: groupOfNames
  cn: s3-writers
  member: uid=ldap-rw,ou=users,dc=s3browser,dc=local
  EOF

  (Khi chép lệnh trên, bỏ 2 dấu cách thụt đầu dòng của phần LDIF và dòng EOF.)

5.3. Bật LDAP cho MinIO, gắn policy và tạo access key

  docker exec minio_s3_browser_test mc idp ldap add local \
    server_addr=openldap_s3_browser_test:389 server_insecure=on \
    lookup_bind_dn=cn=admin,dc=s3browser,dc=local lookup_bind_password='LdapAdmin#2026' \
    user_dn_search_base_dn=ou=users,dc=s3browser,dc=local 'user_dn_search_filter=(uid=%s)' \
    group_search_base_dn=ou=groups,dc=s3browser,dc=local \
    'group_search_filter=(&(objectclass=groupOfNames)(member=%d))'
  docker exec minio_s3_browser_test mc admin service restart local

  docker exec minio_s3_browser_test mc idp ldap policy attach local readwrite \
    --group=cn=s3-writers,ou=groups,dc=s3browser,dc=local
  docker exec minio_s3_browser_test mc idp ldap policy attach local readonly \
    --user=uid=ldap-ro,ou=users,dc=s3browser,dc=local

  docker exec minio_s3_browser_test mc idp ldap accesskey create local ldap-rw \
    --access-key s3b-rw-key --secret-key 'S3bRwKey#2026' --name s3browser-test-rw
  docker exec minio_s3_browser_test mc idp ldap accesskey create local ldap-ro \
    --access-key s3b-ro-key --secret-key 'S3bRoKey#2026' --name s3browser-test-ro

  Lưu ý: tham số user của `accesskey create` là tên ngắn (ldap-rw), không phải DN đầy đủ.

5.4. Bucket cho Anonymous

  docker exec minio_s3_browser_test sh -c '
    for b in anon-public-read anon-public-rw; do mc mb --ignore-existing local/$b; done
    mc anonymous set download local/anon-public-read
    mc anonymous set public local/anon-public-rw
    echo "hello anonymous" > /tmp/hello.txt
    for b in anon-public-read anon-public-rw; do
      mc cp -q /tmp/hello.txt local/$b/hello.txt
      mc cp -q /tmp/hello.txt local/$b/docs/readme.txt
    done
    rm /tmp/hello.txt'

8. Môi trường Floci
-------------------

  Container: local-aws-floci-1 (image floci/floci:latest)
  Endpoint:  http://localhost:4566     Region dùng cho test: ap-southeast-1
  Compose:   kanban-board/docker-compose-local-aws.yml
             docker compose -f docker-compose-local-aws.yml -p local-aws up -d

  Floci mặc định KHÔNG kiểm tra quyền (key nào cũng dùng được). Compose đã bật 3 cờ:
    FLOCI_SERVICES_IAM_ENFORCEMENT_ENABLED=true   kiểm tra IAM policy
    FLOCI_AUTH_VALIDATE_SIGNATURES=true           từ chối access key không tồn tại
    FLOCI_SERVICES_S3_ENFORCE_AUTH=true           áp dụng kiểm tra cho S3

  Tài khoản quản trị (root) của Floci: test / test. Chỉ dùng để dựng môi trường.

  Giới hạn của Floci 1.5.14 (đã kiểm tra, không phải lỗi của app):
    - S3 không kiểm tra secret key: đúng access key + sai secret vẫn được chấp nhận.
      STS và IAM thì có kiểm tra.
    - Request không ký (ẩn danh) luôn được chấp nhận với mọi bucket, kể cả bucket private.
    - Managed policy AWS (AmazonS3FullAccess, AmazonS3ReadOnlyAccess, ...) chỉ là bản giả
      "Allow *", nên phải dùng inline policy tự viết.
    - sts get-caller-identity luôn trả về root, không dùng để kiểm tra danh tính được.

10. Profile cần tạo trong app và kết quả mong đợi
-------------------------------------------------

Mọi profile: Provider = AWS, Endpoint = http://localhost:4566, Region = ap-southeast-1,
Path style bật.

  #      Method           Thông tin nhập                               Kết quả mong đợi
  -----  ---------------  -------------------------------------------  -------------------------------------
  F1     Access key       Key của profile floci-rw                     Liệt kê bucket, upload, xoá được
  F2     Access key       Key của profile floci-ro                     Xem được; upload/xoá báo Access Denied
  F3     Access key       Key của profile floci-assumer                Kết nối báo Access Denied
                                                                       (không có quyền s3:ListAllMyBuckets)
  F4     Access key       AKIAFAKEFAKE / bất kỳ                        Báo key không tồn tại
  F5     AWS CLI profile  Profile floci-rw,                            Như F1
                          Config file ~/.aws/floci-config,
                          Credentials file ~/.aws/floci-credentials
  F6     AWS CLI profile  Profile floci-ro, file như F5                Như F2
  F7     AWS CLI profile  Profile khong-ton-tai, file như F5           Báo profile không tồn tại (S3E033)
  F8     Anonymous        Buckets: s3b-public-read                     Xem và tải file được
  P-DC   Default chain    Mở app với biến môi trường (xem dưới)        Như F1

  Default chain đọc credential từ môi trường của process app, nên phải mở app từ terminal
  đã set biến. PowerShell, trong App/S3Browser:
    $env:AWS_CONFIG_FILE = "$HOME\.aws\floci-config"
    $env:AWS_SHARED_CREDENTIALS_FILE = "$HOME\.aws\floci-credentials"
    $env:AWS_PROFILE = "floci-rw"
    go tool wails3 task dev
  Đổi AWS_PROFILE=floci-ro để thấy upload bị từ chối.

  CHƯA test được trên Floci (giới hạn của app, cần sửa code):
    - Assume role: app tạo STS client không dùng Endpoint của profile
      (internal/modules/bucket/submodule_cfg_credentials.go, assumeRoleCredentials), nên request
      STS đi tới sts.<region>.amazonaws.com (AWS thật) và bị từ chối InvalidClientTokenId.
      AWS CLI profile có role_arn (floci-role-rw) cũng vậy: AWS SDK Go không áp endpoint_url
      cho bước AssumeRole. Riêng AWS CLI (Python) thì chạy đúng:
        aws s3 ls --profile floci-role-rw   -> OK
        aws s3 cp - s3://s3b-private/x.txt --profile floci-role-ro   -> AccessDenied
    - AWS SSO: tương tự, SDK gọi portal/OIDC của AWS thật. Chưa dựng SSO trên Floci.
    - Anonymous không phân biệt được bucket public và private (giới hạn Floci, mục 8).
  Hai method Assume role và AWS SSO cần test trên AWS thật cho đến khi app hỗ trợ endpoint STS.


11. Dựng môi trường Floci từ đầu
--------------------------------

Chạy trong Git Bash. Cần AWS CLI v2. Bật 3 cờ ở mục 8 trong compose rồi
`docker compose ... up -d`, sau đó:

  export AWS_PAGER="" AWS_ACCESS_KEY_ID=test AWS_SECRET_ACCESS_KEY=test
  E="--endpoint-url http://localhost:4566 --region ap-southeast-1"
  RW='{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":"s3:*","Resource":"*"}]}'
  RO='{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":["s3:Get*","s3:List*"],"Resource":"*"}]}'
  ASSUME='{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":"sts:AssumeRole","Resource":"arn:aws:iam::000000000000:role/s3b-*"}]}'
  TRUST='{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"AWS":"arn:aws:iam::000000000000:user/s3b-assumer"},"Action":"sts:AssumeRole"}]}'

  for u in s3b-rw s3b-ro s3b-assumer; do aws iam create-user --user-name $u $E >/dev/null; done
  aws iam put-user-policy --user-name s3b-rw --policy-name s3-rw --policy-document "$RW" $E
  aws iam put-user-policy --user-name s3b-ro --policy-name s3-ro --policy-document "$RO" $E
  aws iam put-user-policy --user-name s3b-assumer --policy-name allow-assume --policy-document "$ASSUME" $E
  aws iam create-role --role-name s3b-role-rw --assume-role-policy-document "$TRUST" $E >/dev/null
  aws iam create-role --role-name s3b-role-ro --assume-role-policy-document "$TRUST" $E >/dev/null
  aws iam put-role-policy --role-name s3b-role-rw --policy-name s3-rw --policy-document "$RW" $E
  aws iam put-role-policy --role-name s3b-role-ro --policy-name s3-ro --policy-document "$RO" $E

  # Ghi access key vào ~/.aws/floci-credentials (dừng nếu file đã có)
  [ -e ~/.aws/floci-credentials ] && echo "floci-credentials đã tồn tại" || \
  for u in rw ro assumer; do
    read -r ak sk < <(aws iam create-access-key --user-name s3b-$u $E \
      --query 'AccessKey.[AccessKeyId,SecretAccessKey]' --output text)
    printf '[floci-%s]\naws_access_key_id = %s\naws_secret_access_key = %s\n\n' $u "$ak" "$sk"
  done > ~/.aws/floci-credentials

  # ~/.aws/floci-config
  { for p in rw ro assumer; do
      printf '[profile floci-%s]\nregion = ap-southeast-1\nendpoint_url = http://localhost:4566\n\n' $p
    done
    for p in rw ro; do
      printf '[profile floci-role-%s]\nregion = ap-southeast-1\nendpoint_url = http://localhost:4566\n' $p
      printf 'role_arn = arn:aws:iam::000000000000:role/s3b-role-%s\nsource_profile = floci-assumer\n\n' $p
    done; } > ~/.aws/floci-config

  # Bucket
  for b in s3b-private s3b-public-read; do
    aws s3api create-bucket --bucket $b --create-bucket-configuration LocationConstraint=ap-southeast-1 $E >/dev/null
    echo "hello floci" | aws s3 cp - s3://$b/hello.txt $E
    echo "hello floci" | aws s3 cp - s3://$b/docs/readme.txt $E
  done
  aws s3api put-bucket-policy --bucket s3b-public-read $E --policy '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":"*","Action":["s3:GetObject","s3:ListBucket"],"Resource":["arn:aws:s3:::s3b-public-read","arn:aws:s3:::s3b-public-read/*"]}]}'

15. Profile cần tạo trong app và kết quả mong đợi
-------------------------------------------------

Mọi profile: Provider = MinIO, Endpoint = https://localhost:10020, Path style bật.
Đường dẫn file bên dưới tính từ certs/ (khi chọn file trong app, chọn file thật trong thư mục đó).

  #    Method       Thông tin nhập                                          Kết quả mong đợi
  ---  -----------  ------------------------------------------------------  ----------------------------------------
  P14  OIDC         Issuer URL = http://localhost:8180/realms/s3browser,     Đăng nhập Keycloak (oidc-user /
                    Client ID = s3browser, Callback port = 48765,            OidcUser#2026), Connect liệt kê
                    CA = ca.pem                                              s3b-tls (policy readwrite)
  P15  OIDC         như P14, Issuer URL = http://localhost:8180/realms/sai   S3E041 (Keycloak không có realm này)
